1、	选题的背景与意义
随着 Web 技术的不断发展，企业和组织内部往往同时运行多个 Web 应用系统。在实际运行过程中，这些系统普遍存在用户身份管理分散、认证方式各自实现、权限控制策略不统一等问题，不仅增加了系统开发和运维成本，也使整体安全防护体系难以形成统一有效的控制，一旦某一系统认证或授权机制设计不当，极易引发越权访问等安全风险。
身份认证与访问控制是 Web 应用安全体系中的基础性安全机制。在多 Web 应用并存的环境下，将身份认证与授权能力从具体业务系统中剥离出来，构建统一的身份认证与访问控制服务，是提升系统安全性、规范性和可管理性的有效途径。
本课题来源于多 Web 应用环境下对统一身份安全管理的实际需求，要求学生设计并实现一个面向 Web 应用的统一身份认证与访问控制服务。该系统以集中式身份认证、访问控制和安全审计为核心，通过标准化接口为多个 Web 应用系统提供统一的安全服务能力，从而降低业务系统重复开发认证与授权功能的成本，提升 Web 应用整体安全防护水平，具有较强的工程实践意义和应用价值。

本毕业设计采用 B/S 架构，围绕统一身份认证与访问控制服务的设计与实现展开。课题要求学生从系统级安全服务的角度出发，将身份认证、会话管理、访问控制和安全审计等功能进行集中设计与实现，构建一个可独立部署、可被多个 Web 应用系统接入的统一安全服务平台
需要完成以下基本功能：
（1）统一身份认证服务模块：设计并实现统一的用户身份认证服务模块，集中处理来自不同 Web 应用系统的用户认证请求。该模块基于用户名和密码的认证方式，采用加盐哈希等安全技术完成用户密码的安全存储与校验，并通过标准化接口对外提供身份认证服务，使认证逻辑不再依赖具体业务系统。
（2）身份凭证与会话管理模块：设计并实现身份凭证与会话管理模块，负责用户认证成功后的身份凭证生成、校验、过期与失效控制。通过统一的会话管理机制，实现用户登录状态的集中维护，支持身份认证结果在多 Web 应用场景下的安全复用，防止会话滥用和非法访问。
（3）基于角色的访问控制模块（RBAC）：设计并实现基于角色的访问控制模块，构建用户、角色、权限与受控资源之间的映射关系。通过集中配置角色与权限，实现对 Web 应用接口和功能的细粒度访问控制，确保用户仅能访问其授权范围内的系统资源，防止未授权访问和越权操作。
（4）统一授权校验接口模块：设计并实现统一的授权校验接口模块，为接入系统提供标准化的身份校验和权限判断服务。业务系统在处理用户请求时，通过调用该模块完成授权决策，从而将权限校验逻辑从业务系统中剥离，体现认证与授权能力的服务化和独立性。
（5）多 Web 应用系统接入管理模块：设计并实现多 Web 应用系统接入管理模块，对接入统一认证服务的业务系统进行集中管理。通过为不同业务系统分配系统标识和接入凭证，实现系统级身份校验，确保只有合法注册的系统才能调用认证与授权接口，体现统一安全服务的可扩展性和独立部署能力。
（6）账户安全控制与风险防护模块：设计并实现账户安全控制与风险防护模块，针对身份认证阶段的常见安全威胁，完成登录失败次数限制、账户临时锁定等安全防护功能，对异常登录行为进行限制和处置，降低暴力破解和非法登录攻击风险。
（7）安全管理与审计模块：设计并实现安全管理与审计模块，对用户身份认证行为、授权决策结果以及异常访问事件进行统一记录和管理。该模块为系统管理员提供安全日志查询、用户状态管理、角色与权限配置以及安全策略维护等功能，实现系统安全策略的集中管理与关键安全行为的可审计性。
（8）系统测试与运行验证模块：对统一身份认证与访问控制服务的各功能模块进行功能测试和安全性测试，重点验证系统在多 Web 应用接入和多用户并发访问场景下的稳定性、正确性和可用性。


在 Web 技术飞速发展的当下，企业和组织内部往往并行运行多个 Web 应用系统。但这些系统普遍存在用户身份管理分散、认证方式各自独立、权限控制策略不统一等问题 —— 这不仅让系统开发时重复构建认证授权功能，增加了开发与运维成本，还导致整体安全防护体系难以形成有效联动，一旦某一系统的认证或授权机制存在设计缺陷，极易引发越权访问、数据泄露等安全风险。
身份认证与访问控制是 Web 应用安全的核心基础机制。在多 Web 应用并存的环境中，将身份认证与授权能力从具体业务系统中剥离，构建独立部署、可复用的统一身份认证与访问控制服务，是提升系统安全性、规范性和可管理性的关键途径。
本课题聚焦多 Web 应用环境下的统一身份安全管理需求，选择 Python 3.8 + 结合 FastAPI 框架构建后端服务 ——FastAPI 的高性能、自动接口文档生成和类型提示特性，能大幅提升开发效率和接口规范性；前端采用原生 HTML、CSS 和 JavaScript 实现操作界面与管理控制台，保证系统轻量性和跨浏览器兼容性；数据库选用 MySQL 存储用户、角色、权限等核心数据，兼顾数据可靠性与查询效率。通过引入加盐哈希等安全技术保障密码存储安全，采用规范的身份凭证管理机制防范会话风险，最终实现一个支持多应用接入、细粒度权限控制、可审计的统一安全服务平台。
该课题的研究与实现，既能解决多 Web 应用环境下身份认证与访问控制的痛点问题，降低业务系统的开发和安全成本，又能提升 Web 应用整体安全防护水平，具有很强的工程实践价值和实际应用场景，同时也能让我深入掌握后端开发、Web 安全、数据库设计等核心技术，提升综合工程实践能力。
2、课题研究的基本内容与拟解决的主要问题
随着互本课题旨在设计并实现一个面向 Web 应用的统一身份认证与访问控制服务，系统采用 B/S 架构，后端基于 Python 3.8 + 和 FastAPI 框架，前端采用原生 HTML/CSS/JavaScript，数据库使用 MySQL，支持 Windows 或 Linux 操作系统部署。具体研究内容如下：
（1）统一身份认证服务模块：基于用户名和密码的认证方式，采用加盐哈希（如 bcrypt 算法）实现用户密码的安全存储与校验，通过 FastAPI 提供标准化认证接口，集中处理多 Web 应用的认证请求，剥离业务系统的认证逻辑。
（2）身份凭证与会话管理模块：设计安全的身份凭证生成、校验、过期与失效机制，采用 JWT（JSON Web Token）或安全会话令牌实现登录状态集中维护，支持多应用场景下的认证结果复用，防范会话劫持、滥用等风险。
（3）基于角色的访问控制（RBAC）模块：构建用户、角色、权限与受控资源的四层映射关系，设计细粒度权限控制策略，支持角色与权限的集中配置，实现对 Web 应用接口和功能的精准访问控制。
（4）统一授权校验接口模块：提供标准化的身份校验和权限判断 API，业务系统通过调用该接口完成授权决策，实现权限校验逻辑与业务系统的解耦，体现服务化特性。
（5）多 Web 应用系统接入管理模块：为接入的业务系统分配唯一标识和接入凭证，实现系统级身份校验，支持接入系统的注册、审核、状态管理，保障只有合法系统才能调用统一安全服务。
（6）账户安全控制与风险防护模块：实现登录失败次数限制、账户临时锁定、异常登录检测等功能，防范暴力破解、非法登录等常见攻击，提升账户安全性。
（7）安全管理与审计模块：记录用户认证行为、授权决策结果、异常访问事件等安全日志，提供日志查询、导出功能；设计系统管理控制台，支持用户状态管理、角色与权限配置、安全策略调整等操作。
（8）系统测试与部署模块：完成功能测试、安全性测试、并发测试，验证系统在多应用接入和高并发场景下的稳定性与可用性；实现系统在 Windows 或 Linux 环境下的部署配置，提供部署文档。
拟解决的主要问题与预期成果：完成一个功能完整、安全可靠、可独立部署的统一身份认证与访问控制服务平台，支持至少 3 个模拟 Web 应用的接入测试，实现用户认证、权限控制、安全审计等核心功能，提交完整的系统源码、数据库脚本、部署文档和测试报告。
3、课题研究方法、设计方案或论文撰写提纲
研究方法：
1.	需求分析方法：通过文献调研（参考 OWASP 安全指南、统一身份认证相关技术文档）、场景分析（模拟多 Web 应用协同办公场景）、需求梳理等方式，明确系统的功能需求（如认证、授权、接入管理）和非功能需求（如安全性、可扩展性、并发性能），编写详细的需求规格说明书。
2.	系统设计方法：采用模块化设计思想，将系统拆分为多个功能独立的模块，明确模块间的交互关系；采用结构化设计方法进行数据库表结构设计和接口设计，确保系统架构清晰、可维护。
3.	开发实现方法：采用迭代开发模式，先完成核心模块（认证、RBAC）的开发与测试，再逐步实现其他功能模块；遵循代码规范，编写注释完善、可复用的代码；结合单元测试、集成测试保障开发质量。
4.	测试验证方法：采用黑盒测试验证功能正确性，白盒测试检查代码逻辑漏洞；通过模拟并发请求测试系统性能；结合 Web 安全测试工具（如 Burp Suite）检测认证、授权等模块的安全风险。
设计方案：
1.	系总体架构设计：系统采用 B/S 架构，分为前端层、后端服务层、数据存储层三层结构。
o	前端层：基于原生 HTML/CSS/JavaScript 实现管理控制台和操作界面，无需依赖复杂框架，保证轻量性和兼容性；通过 AJAX 与后端接口交互，实现数据异步加载和页面动态更新。
o	后端服务层：基于 Python 3.8 + 和 FastAPI 框架构建，包含认证服务、授权服务、接入管理、安全防护、审计日志等核心模块；采用依赖注入、路由分层等设计模式，提升代码复用性和可维护性。
o	数据存储层：使用 MySQL 数据库，设计用户表、角色表、权限表、资源表、应用表、会话表、审计日志表等核心数据表，通过外键关联实现数据完整性约束；采用索引优化提升查询效率。
2.	核心模块设计：
o	统一身份认证模块：用户密码通过加盐哈希处理后存储，认证时通过比对哈希值验证身份；提供 POST 类型的/api/auth/login接口，返回身份凭证（JWT 令牌）；支持凭证过期自动失效、刷新令牌机制。
o	RBAC 模块：设计用户 - 角色（多对多）、角色 - 权限（多对多）、权限 - 资源（一对一）的关联关系；提供角色创建、权限分配、用户角色绑定等接口，支持权限的增删改查操作；授权校验时通过用户角色查询拥有的权限，判断是否允许访问目标资源。
o	多应用接入模块：接入系统需提交注册申请，管理员审核通过后分配app_id和app_secret；业务系统调用统一服务时，需通过app_id和app_secret进行系统身份校验，校验通过后方可发起用户认证、授权查询等请求。
o	安全防护模块：登录失败次数超过阈值（默认 5 次）时，账户临时锁定 15 分钟；记录登录 IP、时间等信息，检测异地登录、频繁登录等异常行为并告警；密码存储采用 bcrypt 算法，盐值随机生成，避免彩虹表破解。
o	审计日志模块：记录用户登录 / 登出、权限变更、应用接入、异常访问等事件，日志包含操作人、操作时间、操作内容、IP 地址等信息；提供日志查询接口，支持按时间范围、操作类型、用户等条件筛选。
3.	数据库设计：
o	用户表（user）：存储用户 ID、用户名、密码哈希、盐值、邮箱、状态（启用 / 禁用）、创建时间等字段。
o	角色表（role）：存储角色 ID、角色名称、描述、创建时间等字段。
o	权限表（permission）：存储权限 ID、权限名称、权限标识、关联资源 ID、描述等字段。
o	资源表（resource）：存储资源 ID、资源名称、资源类型（接口 / 功能）、资源路径、所属应用 ID 等字段。
o	应用表（application）：存储应用 ID（app_id）、应用名称、应用密钥（app_secret）、状态（审核中 / 已启用 / 已禁用）、回调地址等字段。
o	会话表（session）：存储会话 ID、用户 ID、身份凭证、创建时间、过期时间、客户端信息等字段。
o	审计日志表（audit_log）：存储日志 ID、操作人 ID、操作类型、操作内容、IP 地址、操作时间、结果（成功 / 失败）等字段。
4.	接口设计：采用 RESTful 风格设计接口，主要包括认证接口（登录、登出、刷新令牌）、用户管理接口（查询、新增、修改、禁用）、角色权限接口（角色 CRUD、权限分配）、应用接入接口（注册、审核、状态变更）、授权校验接口（权限查询、资源访问校验）、日志查询接口等；所有接口返回 JSON 格式数据，包含状态码、提示信息和响应数据。
